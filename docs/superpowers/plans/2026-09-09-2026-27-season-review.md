# 2026-27 Season Support and Full Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update One Rugby Navi2 for the 2026-27 League One season, including the official D1/D2/D3 annual schedules and changed team composition/names, while fixing season-sensitive defects and improving UI consistency.

**Architecture:** Keep the existing web schedule + cache flow, but make the official `content/schedule_table/{season}/{division}` pages the primary regular-season source and use `/schedule/?year={season}` as the richer/fallback source for results and special matches. Centralize season/team/UI constants so future season changes do not require scattered hard-coded edits. Preserve the existing SQLite seed database and cache safety behavior; do not overwrite user data.

**Tech Stack:** .NET 9, .NET MAUI Android, C#, HtmlAgilityPack, Microsoft.Data.Sqlite.

**Spec:** `OneRugbyNavi2_SPECIFICATION_UPDATED.md`

## Global Constraints

- Official League One pages are the source of truth; do not infer missing fixture data.
- 2026-27 regular schedules use `https://league-one.jp/content/schedule_table/2026/div1`, `/div2`, and `/div3`.
- 2026-27 team composition is 12 teams in D1, 8 in D2, and 7 in D3.
- D1 has no conference split in 2026-27.
- Preserve offline schedule cache behavior and existing user preferences.
- Do not replace the packaged SQLite database unless a newer packaged seed is available.
- Do not add guessed logos for new/rebranded teams; use an existing asset only when it is the same club identity and the asset remains acceptable, otherwise fall back to the badge UI.
